# Contract: плагин `svgshaper-bevy`

Тонкий адаптер Bevy 0.20 поверх `svgshaper`. Доменную конвертацию плагин не
повторяет. Типы Bevy не появляются в крейте ядра.

## Подключение

Хост вызывает `app.add_plugins(SvgShaperPlugin)` один раз. Импорт плагина сам
по себе конвертацию не начинает и ресурсы молча не создаёт, кроме регистрации
типа события итога, которую делает `Plugin::build`.

Зависимость Bevy у этого крейта с `default-features = false`. Окно и GPU для
контракта не нужны.

## Работа системы

Система читает запрос, который хост положил в мир, и `StopFlag`. Future ядра
`convert` порождается в пуле задач Bevy так, чтобы главный поток кадра не
блокировался на чтении, растеризации и записи.

Пока future не готова, система не ждёт её синхронно до конца пакета. Когда
итог готов, система через `bevy::prelude::Commands` публикует событие с
`Result<ConversionReport, RequestError>` ядра. Состав отчёта тот же, что в
`contracts/convert-api.md`.

Процесс `rsvg-convert` запускает ядро через `std::process::Command`.
`bevy::prelude::Commands` только публикует уже готовый отчёт в ECS. Плагин
свою команду не собирает.

## Наблюдаемый результат

После `add_plugins` и постановки одного запроса хост без окна получает ровно
один итог ядра: принятый отчёт по источникам или ошибку отклонения запроса.
Успешный PNG на диске удовлетворяет контракту ядра.
