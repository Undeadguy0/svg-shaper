# Data Model: Конвертация SVG в PNG

Типы ниже — публичный контракт ядра. Плагин Bevy их не переопределяет, а
переносит в событие ECS. Имена полей можно уточнить при реализации, смысл и
правила — нет.

## ConversionRequest

Один запрос пользователя.

| Поле | Смысл | Правило |
|---|---|---|
| sources | Пути к файлам и папкам | Пустой список отклоняет весь запрос до записи |
| width | Ширина PNG в пикселях | Целое от 1 до 16384 включительно |
| height | Высота PNG в пикселях | То же |
| destination | Папка для всех PNG | `None`: каждый PNG рядом со своим SVG. Иначе папка создаётся до записи, если это возможно |
| prefix | Текст `{prefix}` | По умолчанию пустая строка |
| suffix | Текст `{suffix}` | По умолчанию пустая строка |
| template | Шаблон имени | По умолчанию `{prefix}{name}{suffix}.png` |
| replace | Заменять существующий файл | По умолчанию `false` |
| converter | Путь или имя программы растеризации | По умолчанию `rsvg-convert`. Ищется в `PATH`, если это не путь |

Связи: запрос порождает ноль или больше `Source` после раскрытия папок и
затем один `ConversionReport`.

Отклонение запроса целиком, без новых файлов:

- размер вне диапазона или не целый;
- нет ни одного пути;
- префикс, суффикс или шаблон дают пустое имя, `.`, `..` или содержат
  разделитель пути;
- папку назначения нельзя создать;
- программу растеризации нельзя запустить (`ConverterUnavailable`).

## Source

Один SVG после раскрытия папок и снятия повторов.

| Поле | Смысл | Правило |
|---|---|---|
| path | Путь к файлу | Повтор того же пути в запросе схлопывается в один источник |
| stem | `{name}` | Имя файла без последнего расширения |

Правила отбора:

- Папка и путь-папка: только непосредственные потомки, чьё имя оканчивается
  на `.svg` без учёта регистра.
- Подпапки и ссылки на папки не открываются.
- Прочие потомки папки пропускаются и не становятся источниками.
- Явный путь к файлу не-SVG — источник с неуспехом «файл не SVG».
- Сломанная ссылка и имя на `.svg`, которое не является файлом, — неуспех
  этого источника.

## OutputName

Результат шаблона для одного источника.

| Поле | Смысл |
|---|---|
| directory | Папка назначения источника |
| file_name | Имя файла внутри этой папки |
| path | `directory` + `file_name` |

Правила:

- Подстановки только `{prefix}`, `{name}`, `{suffix}`. Прочий текст шаблона
  буквальный.
- Если имя не оканчивается на `.png` без учёта регистра, добавляется `.png`.
  Уже оканчивающееся на `.png` не удваивается.
- `path` остаётся внутри `directory`.
- Два источника одного запроса с одним `path`: оба неуспешны, «совпадение
  имён», файл не пишется.

## RenderedPng

PNG, который процесс записал во временный файл до переименования.

| Поле | Смысл | Правило |
|---|---|---|
| width, height | Поля IHDR | Ровно запрошенные, иначе файл не публикуется |
| path | Временный путь | Лежит в папке назначения. После успеха становится конечным именем |

Процесс — `std::process::Command` без `sh -c`. Ему передаются только эта
программа, ширина, высота, формат `png`, временный путь и один SVG. Чужие
файлы и сетевые адреса в аргументы не входят. Пропорции не сохраняются:
`--keep-aspect-ratio` не передаётся.

## SourceOutcome

Итог одного источника. Ровно одно из трёх состояний.

```text
Pending → Running → Succeeded(path)
                 → Failed(reason)
                 → Stopped
```

- `Succeeded`: целый PNG по `path`. Код выхода был нулевым, ширина и высота
  совпали с запросом. Сходство рисунка на произвольном файле отдельно не
  проверяется. Контрольный набор подтверждается автопроверкой областей.
- `Failed`: нового файла нет. При замене прежний файл не изменён.
- `Stopped`: остановка запроса. Нового незавершённого файла нет. Уже
  успешные источники этого запроса не откатываются.

Причины `Failed`, которые вызывающий код различает:

| Причина | Когда |
|---|---|
| `NotFound` | Пути нет |
| `Unreadable` | Файл нельзя прочитать |
| `NotSvg` | Явный путь не оканчивается на `.svg` |
| `NotAFile` | Имя на `.svg` не является файлом, либо ссылка сломана |
| `CannotDraw` | SVG нельзя нарисовать из самого файла |
| `NameTaken` | Конечный файл уже есть, замена выключена |
| `NameCollision` | Несколько источников одного запроса сошлись в один путь |
| `ConcurrentWrite` | Другой запрос этого процесса уже занимает тот же путь |
| `WriteFailed` | Папка или файл назначения не принимают запись |

`Stopped` не смешивается с этими причинами.

## ConversionReport

Запрос дошёл до обработки источников.

| Поле | Смысл |
|---|---|
| outcomes | Итог каждого взятого в работу источника, в порядке обработки |

Пропущенные не-SVG элементы папки в список не входят.

Отклонённый запрос отчётом источников не является: это ошибка запроса
`InvalidSize`, `EmptySources`, `InvalidName` или `DestinationUnavailable`.

## StopFlag

Флаг остановки, который можно поднять, пока `convert` ещё выполняется.

Переход: между источниками и до переименования временного файла ядро читает
флаг. Поднятый флаг переводит текущий незавершённый источник и все
последующие в `Stopped`. Уже переименованные PNG остаются `Succeeded`.

## OutputClaim

Процессная занятость конечного пути на время одного источника.

```text
свободен → занят этим запросом → свободен
                ↘ другой запрос получает ConcurrentWrite и путь не трогает
```

Кто занял путь первым, тот пишет. Второй не заменяет и не усекает файл
первого, даже если у второго включена замена.

## Bevy-проекция

Плагин не вводит новых доменных полей. `ConversionRequest`, `StopFlag` и
`ConversionReport` приходят из ядра. Готовый отчёт плагин кладёт в событие
ECS через `Commands`.
