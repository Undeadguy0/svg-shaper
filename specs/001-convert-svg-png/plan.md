# Implementation Plan: Конвертация SVG в PNG

**Branch**: `001-convert-svg-png` | **Date**: 2026-11-17 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-convert-svg-png/spec.md`

## Summary

Библиотека принимает пути к SVG или папку без вложенности и пишет PNG
заданной ширины и высоты. Имя собирается шаблоном `{prefix}{name}{suffix}.png`,
папку назначения можно задать. Уже записанные файлы при остановке остаются,
незавершённый файл не публикуется. Два одновременных запроса к одному пути
оставляют один целый PNG.

Технически это Rust-ядро `svgshaper`. Файлы обходятся асинхронно. Рисунок
делает отдельный процесс: `std::process::Command` запускает `rsvg-convert`
без интерпретатора оболочки и без `--keep-aspect-ratio`. Успех источника —
нулевой код выхода и PNG запрошенного размера. Сходство рисунка проверяет
отдельный прогон контрольного набора, когда `rsvg-convert` есть в `PATH`.
Ожидание процесса не блокирует поток вызывающего. Плагин `svgshaper-bevy`
только вызывает ядро и кладёт готовый отчёт в ECS. Решения — в
[research.md](research.md). Уточнения 2026-11-18 записаны в [spec.md](spec.md).

## Technical Context

**Language/Version**: Rust, edition 2024. MSRV ядра 1.85. MSRV крейта плагина
1.97.1 (пол Bevy 0.20.1).

**Primary Dependencies**: `std::process::Command`, `blocking` для ожидания
процесса и файловых вызовов. Программа по умолчанию: `rsvg-convert` (librsvg)
в `PATH`. Плагин: `bevy` 0.20 с `default-features = false`. Тестовая
программа `svgshaper-test-converter` собирается Cargo и не публикуется как
продукт.

**Storage**: Файлы SVG и PNG на локальной файловой системе. Базы данных нет.

**Testing**: `cargo test -p svgshaper` проверяет файловый контракт ядра через
`svgshaper-test-converter` и не требует системный `rsvg-convert`. Тот же пакет
содержит проверку областей контрольного набора из SC-007: тест выполняется,
когда `rsvg-convert` найден в `PATH`, и пропускается, когда его нет. Пропуск
не роняет файловый набор. `cargo test -p svgshaper-bevy` проверяет плагин без
окна и GPU и тоже подставляет тестовую программу.

**Target Platform**: Обычные ОС, где работают Rust и файлы (Linux — основная
среда разработки). WASM и мобильные цели этой фичей не обещаются.

**Project Type**: Библиотека плюс необязательный крейт плагина Bevy.
Обязательного бинарника нет.

**Performance Goals**: Числовой цели по времени спецификация не задаёт.
Обязательство: опрос future не блокирует поток вызывающего на время ожидания
`rsvg-convert` и записи. Пока дочерний процесс ещё спит, `poll` возвращает
управление вызывающему потоку. Источники одного запроса обрабатываются по
очереди.

**Constraints**: Сторона PNG от 1 до 16384 пикселей, только целые. Процесс
запускается без `sh -c` и получает только путь одного SVG и путь временного
PNG. Ядро сеть не открывает и чужие пути в аргументы не кладёт. Относительную
ссылку, которую откроет сам `rsvg-convert`, библиотека не запрещает. Успех
источника — нулевой код выхода и IHDR запрошенного размера. Отдельной проверки
«эффект тихо пропал» нет. Текст контрольного набора рисуется системным
`sans-serif`; файл шрифта рядом с SVG не подкладывается. Подпапки не
обходятся. Замена существующих файлов выключена, пока её не включили. Запись
чужого процесса в тот же путь не координируется. Если `rsvg-convert` нельзя
запустить, запрос отклоняется с `ConverterUnavailable` до записи.

**Scale/Scope**: Один запрос — выбранные файлы или один уровень папки. Предел
числа файлов не задан. Продукт — ядро и плагин. Тестовая программа в поставку
не входит.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

Принципы — `.specify/memory/constitution.md` v1.0.0.

| Принцип | До исследования | После проектирования |
|---|---|---|
| I. Чистая библиотечная архитектура | Ядро — библиотека. Домен не зависит от бинарника, UI и Bevy. | Проходит. `crates/svgshaper` держит домен. Плагин только вызывает `convert`. |
| II. Rust как язык реализации | Весь код на Rust. Ошибки через `Result`. MSRV будет объявлен в манифестах. | Проходит. `RequestError` и причины источника — `Result` и перечисления. Паника только на внутренний инвариант. `unsafe` не требуется. |
| III. Базовые тесты обязательны | `cargo test` ядра без Bevy, GPU, дисплея, сети и внешних сервисов. | Проходит. `cargo test -p svgshaper` запускает тестовую программу Cargo и не требует системный `rsvg-convert`. Проверка областей SC-007 входит в тот же пакет и выполняется только когда `rsvg-convert` есть в `PATH`; без программы тест пропускается, файловый набор остаётся зелёным. Плагин тестируется отдельно и без окна. |
| IV. Асинхронное ядро | Ожидание и файлы — `async`. Публичные типы без имени runtime. Отмена видна в итоге. | Проходит. `blocking` спрятан внутри. Тест опрашивает future, пока тестовая программа спит, и убеждается, что `poll` вернул управление раньше конца сна. `StopFlag` даёт итог `Stopped` и не оставляет временный файл конечным PNG. |
| V. Интеграция в Bevy как плагин | Bevy выключен по умолчанию. Один `add_plugins`. Доменные типы не знают Bevy. | Проходит. Отдельный крейт `svgshaper-bevy` вызывает `convert`. Процесс запускает ядро. В ECS отчёт кладётся командным буфером Bevy. |

Нарушений нет. Отдельный крейт плагина разрешён принципом V и нужен, чтобы
MSRV Bevy 1.97.1 не стал полом ядра.

ссылается на плагин. Обязательного бинарника и каталога `src/` в корне нет.
