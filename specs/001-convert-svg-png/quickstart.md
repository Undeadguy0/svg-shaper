# Quickstart: проверка конвертации SVG в PNG

Руководство прогона, не реализация. Контракты:
[ядро](contracts/convert-api.md), [плагин Bevy](contracts/bevy-plugin.md).
Поля: [data-model.md](data-model.md).

## Предусловия

- Rust не ниже 1.85 для ядра и не ниже 1.97.1 для крейта плагина.
- Сеть, GPU и дисплей не нужны.
- `cargo test` не требует системный `rsvg-convert`: тесты подставляют
  программу `svgshaper-test-converter`, собранную Cargo.
- Прогон настоящего растеризатора требует `rsvg-convert` в `PATH`.
- Команды выполняются из корня репозитория.

## Сборка и тесты

Ядро, без Bevy:

```text
cargo test -p svgshaper
```

Ожидание: команда завершается успешно. Тесты сами создают временные папки.

Плагин, без окна и GPU:

```text
cargo test -p svgshaper-bevy
```

Ожидание: команда завершается успешно. Тест поднимает приложение Bevy с
`SvgShaperPlugin` и читает событие итога.

## Сценарии, которые должны стать зелёными

Каждый сценарий вызывает публичный `convert` и проверяет отчёт и файлы.
В запрос файловых тестов передан путь `svgshaper-test-converter`. Эталонные SVG
лежат рядом с тестом. Сценарии размера, имён, папки, остановки и одновременной
записи проверяет тестовая программа. Сценарии рисунка 8 и 9 передают в запрос
`rsvg-convert`. Если программы нет в `PATH`, эти два сценария пропускаются, а
остальной `cargo test -p svgshaper` остаётся зелёным.

1. Один `logo.svg`, 64×32, без папки и без своего шаблона. Рядом появляется
   `logo.png` ровно 64×32. Отчёт — успех с этим путём.
2. Два явных SVG, 128×128. Два PNG рядом со своими исходниками, оба 128×128.
3. Ширина 0, отрицательная высота или дробный размер. Ошибка
   `InvalidSize`, новых файлов нет.
4. Пустой список путей. Ошибка `EmptySources`, новых файлов нет.
5. В одном запросе годный SVG и отсутствующий путь. Годный становится PNG,
   отсутствующий — `NotFound`.
6. Явный `notes.txt`. Итог `NotSvg`, PNG нет.
7. Рядом уже лежит PNG с именем по умолчанию, замена выключена. Прежний файл
   не меняется, итог `NameTaken`.
8. Контрольный SVG с прозрачной областью, прогон с `rsvg-convert`. Точка
   прозрачной области имеет нулевую непрозрачность, точка заливки непрозрачна.
   Сплошной заливки прозрачной области нет. Без `rsvg-convert` сценарий
   пропускается.
9. Контрольный набор с `rsvg-convert` по SC-007: фигура, контур, заливка,
   обводка, прозрачность, градиент, простой текст семейством `sans-serif`,
   фильтр, маска, обрезка, маркер, начальный вид анимации. Файла шрифта рядом
   нет. Каждая автопроверка области проходит, размер равен запрошенному.
   Без `rsvg-convert` сценарий пропускается.
10. Тестовая программа завершается с `--exit-code 1`. Итог `CannotDraw`,
    нового PNG нет. Ядро само внешний путь не открывает.
11. Растеризатор завершается успешно, в SVG есть и внутренняя фигура, и
    внешняя ссылка. Итог успешный, размер совпал. Библиотека не обещает, что
    дочерний процесс не открыл относительную ссылку.
12. Папка: `a.svg`, `b.SVG`, `notes.txt`, `nested/c.svg`. Запрос папки даёт
    только `a.png` и `b.png`. Вложенный SVG не конвертируется, `notes.txt` не
    является неуспехом.
13. Папка без SVG. Успешный отчёт без источников и без новых файлов.
14. Один и тот же путь дважды. Один PNG и один успех.
15. Путь к папке в списке конкретных путей ведёт себя как сценарий 12.
16. `icons/logo.svg`, папка `out`, префикс `ico_`, суффикс `_2x`, шаблон по
    умолчанию. Появляется `out/ico_logo_2x.png`. Рядом с исходником нового
    PNG нет. Если `out` не существовала, она создаётся.
17. Два исходника сходятся в одно имя. Оба `NameCollision`, файла нет.
18. Префикс с разделителем пути. Ошибка `InvalidName` до записи.
19. Замена включена и конечный файл уже есть. После успеха это PNG
    запрошенного размера. Если SVG нельзя нарисовать, прежний файл остаётся.
20. Шаблон без окончания получает одно `.png`. Шаблон, уже оканчивающийся на
    `.png`, не становится `.png.png`.
21. Папку назначения создать нельзя. Ошибка `DestinationUnavailable`, новых
    файлов нет.
22. Два одновременных запроса в один и тот же путь, в том числе с заменой.
    Ровно один успех и один `ConcurrentWrite`. Файл — целый PNG успешного
    запроса.
23. Папка из трёх SVG. После целого первого PNG запрос останавливают, пока
    второй ещё пишется. Первый файл остаётся. Второй и третий — `Stopped`.
    Незавершённого PNG нет. Если второй заменял существующий файл, прежний
    файл остаётся.
24. Плагин: `add_plugins(SvgShaperPlugin)`, один запрос, без окна. В мире
    появляется один итог ядра, PNG на диске совпадает с контрактом ядра.
    Главный поток не ждёт весь пакет синхронно.
25. Явный `logo.SVG`. Это SVG, появляется PNG запрошенного размера.
26. В одном запросе годный SVG, нечитаемый файл и сломанная ссылка с именем
    на `.svg`. Годный становится PNG. Нечитаемый — `Unreadable`. Сломанная
    ссылка и имя на `.svg`, которое не является файлом, — `NotAFile`.
27. `converter` указывает на программу, которой нет. Ошибка
    `ConverterUnavailable` до записи, новых файлов нет.
28. Источник — ссылка на папку, внутри которой лежит SVG. Этот SVG не
    конвертируется.
29. Папка назначения существует. Один выходной путь занят каталогом, второй
    источник годен. Первый — `WriteFailed`, второй становится PNG.
30. Тестовая программа запущена с `--sleep-ms 300`. Пока она спит, опрос
    future возвращает управление вызывающему потоку быстрее, чем за 100 мс.

Сценарии 1–7 и 25–27 закрывают историю P1 на заглушке. Сценарии 8–9 закрывают
рисунок и требуют `rsvg-convert`. Сценарии 12–15 и 28 закрывают P2. Сценарии
16–21 и 29 закрывают P3. Сценарии 10–11, 22, 23 и 30 закрывают уточнения.
Сценарий 24 закрывает плагин.
