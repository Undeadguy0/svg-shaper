# Research: Конвертация SVG в PNG

## 1. Растеризация через оболочку

**Decision**: Каждый SVG рисует отдельный процесс, запущенный через
`std::process::Command`. Интерпретатор оболочки (`sh -c`) не используется:
программа и аргументы передаются списком. Программа по умолчанию —
`rsvg-convert` из librsvg. Вызывающий код может подставить другой путь к
программе в запросе.

Аргументы по умолчанию:

```text
rsvg-convert --width {width} --height {height} --format png --output {temp} {source}
```

Флаг `--keep-aspect-ratio` не передаётся. В man rsvg-convert пропорции
сохраняются только с этим флагом; без него запрошенные ширина и высота
задают размер картинки. `--background-color` не передаётся: фон по умолчанию
прозрачный. В аргументах нет чужих файлов и нет `--base-uri` на папку
источника.

Перед публикацией ядро читает IHDR записанного PNG. Если ширина или высота
не равны запросу, временный файл удаляется, источник получает «рисунок нельзя
построить». Ненулевой код выхода процесса — та же причина. Если программу
нельзя запустить, весь запрос отклоняется с `ConverterUnavailable`, новых
файлов нет.

**Rationale**: Уточнение к плану: «доступ к оболочке» означает
`std::process::Command`, а не командный буфер Bevy. librsvg покрывает фигуры,
текст, фильтры, маски, обрезку и маркеры. Точный размер без сохранения
пропорций совпадает со спецификацией, если не передавать
`--keep-aspect-ratio`.

Процесс получает только путь одного SVG и путь временного PNG. Сетевой адрес
ядро не открывает и в аргументы не кладёт. Ограничение, принятое 2026-11-18:
сам `rsvg-convert` может открыть относительную ссылку внутри SVG. Ядро
дополнительных путей не передаёт и песочницу вокруг процесса не ставит. Если
из-за недоступного внешнего ресурса процесс завершается с ошибкой или пишет
PNG другого размера, источник неуспешен. Если процесс завершается с кодом 0 и
размер совпал, итог успешный.

Успех произвольного источника не включает поиск «эффект тихо пропал». Фильтр,
маска, обрезка и маркер подтверждаются только автопроверкой областей
контрольного набора. Текст этого набора задаёт `sans-serif`. librsvg рисует
текст системными шрифтами через Pango и не использует шрифт, встроенный в SVG,
и файл шрифта рядом с SVG. Если буквы нарисовать нельзя, источник неуспешен.

Тесты файлового контракта не требуют установленный `rsvg-convert`. Cargo
собирает тестовую программу `svgshaper-test-converter`, и тесты передают её
путь в запрос. Она запускается через `std::process::Command`, умеет
`--sleep-ms` и `--exit-code`, и пишет PNG запрошенного размера. Это не внешний
сервис. Проверка областей SC-007 живёт в том же пакете тестов: когда
`rsvg-convert` есть в `PATH`, она выполняется, иначе пропускается и не роняет
файловый набор.

**Alternatives considered**:

- Встроенный `resvg` 0.50. Закрывает спецификацию без внешней программы, но
  отвергнут: доступ к оболочке задан как `std::process::Command`.
- `sh -c` с одной строкой. Ломается на пробелах в путях и смешивает аргументы
  с оболочкой.
- Inkscape. Тяжелее, дольше стартует на каждый файл, для пакета хуже
  `rsvg-convert`.

## 2. Асинхронная работа с файлами

**Decision**: Публичный контракт — `async fn` на `std::future`. Обход папки,
ожидание процесса и публикация PNG выполняются так, чтобы поток
вызывающего не блокировался. Ожидание `Child` и файловые вызовы идут через
пул `blocking`. Публичные типы не называют `tokio`, `async-std` или
исполнитель Bevy.

`Command::spawn` вызывается в этом пуле. Поток пула крутит `try_wait` и
смотрит `StopFlag`. При остановке процесс получает `Child::kill`, временный
файл удаляется, источник становится `Stopped`. Уже переименованные PNG
остаются. Итог запроса возвращается.

Запись процесса идёт во временный файл в папке назначения. Конечное имя
появляется атомарным переименованием только после целого PNG нужного размера.
Ошибка и остановка до переименования удаляют временный файл и не усекают
прежний конечный файл.

Внутри одного запроса источники идут по очереди. Отдельный предел числа
файлов и цель по времени спецификация не задаёт.

**Rationale**: `Command::output` блокирует до конца процесса. Прямой вызов с
async-потока Bevy остановил бы кадр. `tokio::process` поставил бы Tokio в
публичный API, что запрещает конституция. `blocking` оставляет future
опрашиваемой любым исполнителем.

**Alternatives considered**:

- Прямой `std::fs` и `Command::output` внутри `async fn`. Блокирует поток
  вызывающего.
- `tokio::fs` и `tokio::process`. Нарушают принцип IV.

## 3. Плагин Bevy

**Decision**: Плагин остаётся отдельным крейтом `svgshaper-bevy` и не рисует
SVG сам. Он вызывает `svgshaper::convert`. Процесс запускает ядро. В мир ECS
готовый отчёт кладёт система через `bevy::prelude::Commands`. Это командный
буфер Bevy, не оболочка ОС.

Bevy 0.20.1 (crates.io, 2026-10-28) имеет MSRV 1.97.1. Ядро остаётся на MSRV
1.85 из-за edition 2024. Отдельный крейт не поднимает пол компилятора для
пользователей без Bevy. Конституция это разрешает.

Плагин порождает future ядра в пуле задач Bevy 0.20 вне главного потока.
Точное имя пула сверяется с docs.rs bevy 0.20 при реализации. Наблюдаемый
эффект: кадр не блокируется, в ECS появляется один итог.

Тест плагина поднимает `App` без окна и без GPU и тоже передаёт тестовую
программу-конвертер, а не системный `rsvg-convert`.

**Alternatives considered**:

- Считать `bevy::prelude::Commands` доступом к оболочке. Это была ошибка
  плана. Пользователь уточнил: имеется в виду `std::process::Command`.
- Feature `bevy` в крейте ядра. Поднимает MSRV ядра до 1.97.1.
- Плагин, который сам собирает `Command`. Дублирует домен и нарушает принцип V.

## 4. Одновременная запись одного пути

**Decision**: На время запроса путь конечного PNG занимается в процессной
таблице `Mutex<HashSet<PathBuf>>`. Второй запрос этого же процесса сразу
получает «одновременная запись» и не запускает процесс в этот путь. Кто занял
путь первым, тот и успешен. После переименования или отказа путь
освобождается.

Совпадение имён внутри одного запроса считается до запуска процесса: такие
источники все неуспешны, путь в таблицу не занимается.

Замена выключена по умолчанию: если конечный файл уже есть, источник
неуспешен с «имя уже занято», процесс не запускается. Замена включена:
временный файл переименовывается поверх только после целого PNG нужного
размера.

**Rationale**: Спецификация требует один целый PNG и второй неуспех, без
порчи файла победителя, даже при включённой замене. Захват до `Command::spawn`
не даёт второму запросу начать запись. Атомарное переименование не оставляет
обрезанный PNG. Запись из программы вне svgshaper спецификация не покрывает.

**Alternatives considered**:

- Последний записавший побеждает. Может оставить обрезанный файл.
- Глобальная очередь всех запросов. Лишняя сериализация несвязанных путей.
- `flock` на каждый файл. Нужен для чужих процессов, которые спецификация
  прямо исключает.
